Imagen a Base64

Elige una imagen y obtén al instante su versión en Base64: como data URI completa para HTML y CSS, como Base64 sin más para APIs y JSON, o ya envuelta en una etiqueta img o en un background-image. Todo se procesa en tu navegador, así que tu imagen nunca se sube a ningún servidor.

Para qué convertir una imagen a Base64

Convertir una imagen a Base64 sirve para meter la imagen dentro de un archivo de texto. En lugar de un archivo separado que hay que enlazar, subir y mantener, la imagen viaja como una cadena de texto dentro del propio HTML, del CSS, de un JSON o de un correo. Eso es útil en prototipos rápidos, en plantillas de correo (donde los archivos adjuntos se bloquean con frecuencia), en APIs que solo aceptan JSON y en documentos HTML de un solo archivo que deben funcionar sin depender de ninguna carpeta de imágenes.

También es el formato que muchas APIs esperan cuando les envías una imagen: en vez de un archivo, reciben una cadena Base64 dentro del JSON. Y es la forma habitual de incrustar iconos pequeños y logos en CSS sin una petición extra al servidor por cada imagen. Eso sí: solo compensa con imágenes pequeñas. Una foto grande en Base64 pesa un tercio más que el archivo original y hace que la página cargue más lenta, así que para fotos grandes sigue siendo mejor enlazar el archivo.

Cómo convertir una imagen a Base64

  1. Haz clic en elegir archivo y selecciona tu imagen: PNG, JPG, GIF, WebP o cualquier otro formato de imagen.
  2. Elige el formato de salida: data URI completa (para HTML y CSS), solo Base64 (para APIs y JSON), etiqueta HTML img o CSS background-image.
  3. Revisa los datos: formato detectado, tamaño original, dimensiones y número de caracteres Base64 generados.
  4. Copia la salida con "Copiar salida" o descárgala como archivo .txt para guardarla o enviarla.

Ejemplo práctico

Pulsa "Probar una imagen de ejemplo" y verás un caso real: un PNG de 416 bytes se convierte en 556 caracteres Base64. La data URI completa mide 578 caracteres, porque añade el prefijo data:image/png;base64, delante de la cadena.

Es decir, la imagen crece aproximadamente un 33,7 % al pasar a Base64. Con una imagen de muestra tan pequeña el aumento es de apenas 140 caracteres; con una foto de 2 MB serían unos 2,7 MB de texto. Ese es el cálculo que debes hacer antes de incrustar una imagen grande en una página: el ahorro de una petición al servidor rara vez compensa ese peso extra.

Consejos prácticos

  • Elige bien el formato de salida. Para pegar en HTML usa la data URI o la etiqueta img ya generada; para enviar a una API, el Base64 solo, porque la mayoría de APIs no quieren el prefijo data:… y lo rechazan.
  • Comprime antes de convertir. Si la imagen va a una web, pásala primero por el compresor de imágenes: cada kilobyte que recortes antes se traduce en un 33 % menos de texto después.
  • Usa Base64 para iconos y logos pequeños, no para fotos. La regla práctica: por debajo de unos pocos KB, incrustar compensa; por encima, enlaza el archivo y deja que el navegador lo cachee.
  • Guarda la salida en .txt si es larga. Una cadena de miles de caracteres es fácil de romper al copiarla desde un chat. El archivo descargado conserva cada carácter intacto.

Errores comunes que debes evitar

  • Enviar la data URI completa a una API que pide Base64 solo. Es el error más habitual: la API espera la cadena y recibe data:image/png;base64,… delante, y la rechaza. Cambia el formato de salida a "Solo Base64" antes de copiar.
  • Incrustar fotos grandes en HTML. Una foto de 3 MB se convierte en 4 MB de texto dentro del HTML, la página no se puede cachear bien y cada visita vuelve a descargar esos 4 MB. Para fotos, enlaza el archivo.
  • Olvidar que el Base64 no es privado. Cualquiera que vea la cadena puede decodificarla y recuperar la imagen. No uses este método para "ocultar" imágenes sensibles.
  • Elegir un archivo que no es una imagen. Si seleccionas un PDF o un documento, la herramienta te avisará de que no es una imagen: solo acepta archivos de imagen reales.

Preguntas frecuentes

¿Cuánto crece una imagen al convertirla a Base64?

Alrededor de un 33 %. Cada 3 bytes de la imagen se representan con 4 caracteres de texto. El ejemplo de esta página lo muestra con cifras reales: un PNG de 416 bytes produce 556 caracteres Base64, y la data URI completa, con su prefijo, mide 578 caracteres.

¿Qué diferencia hay entre la data URI y el Base64 solo?

La data URI es la cadena Base64 precedida de data:[tipo];base64, (por ejemplo data:image/png;base64,). Los navegadores necesitan ese prefijo para saber qué tipo de archivo es. Las APIs, en cambio, suelen pedir solo la cadena, porque ellas ya saben qué formato esperan.

¿Puedo pegar el resultado directamente en mi página web?

Sí. Elige el formato «Etiqueta HTML img» y pega el resultado tal cual en tu HTML, o elige «CSS background-image» para usarlo en tu hoja de estilos. Funciona sin subir ningún archivo, porque la imagen viaja dentro del propio código.

¿Mi imagen se sube a algún servidor?

No. La lectura y la conversión ocurren en tu navegador con JavaScript. La imagen nunca sale de tu dispositivo, así que puedes convertir fotos privadas o de trabajo sin riesgo.

¿Hay un límite de tamaño para la imagen?

No hay un límite establecido, pero las imágenes muy grandes generan cadenas enormes que pueden hacer lento el navegador al copiarlas o al pegarlas en un editor. Para imágenes grandes, comprime primero y convierte después.

¿Por qué a veces no se muestra la vista previa?

Algunos formatos de imagen no se pueden previsualizar en todos los navegadores, aunque la conversión a Base64 se haya hecho correctamente. En ese caso verás el aviso de vista previa no disponible, pero la cadena generada sigue siendo válida y copiable.
