Formateador JSON

Pega un JSON en una sola línea ilegible y devuélvelo formateado con sangría, minificado para enviarlo, o simplemente validado para saber si tiene algún error. Es la herramienta de todos los días para quien trabaja con APIs, archivos de configuración o datos: pega, pulsa un botón y el JSON queda legible o listo para enviar.

Qué es JSON y por qué se desordena tanto

JSON (JavaScript Object Notation) es el formato de datos más usado en la web: las APIs lo devuelven, las apps lo guardan y los archivos de configuración lo usan. Su problema es que las máquinas lo escriben sin saltos de línea ni espacios, en una sola línea larguísima, porque a ellas no les hace falta que sea legible. A las personas, sí: un JSON minificado de una API es prácticamente imposible de revisar a ojo, y un solo carácter fuera de sitio (una coma de más, una comilla simple) lo invalida por completo.

Por eso existen tres operaciones básicas, y esta herramienta hace las tres. Formatear añade saltos de línea y sangría para que la estructura se vea de un vistazo. Minificar hace lo contrario: quita todos los espacios innecesarios para que el JSON pese lo menos posible al enviarlo. Validar solo comprueba si el JSON es correcto, sin cambiarlo, y te dice dónde está el error si lo hay.

Cómo formatear, minificar o validar JSON

  1. Pega tu JSON en el cuadro de entrada, tal cual te llegó: en una línea, con saltos de línea, da igual.
  2. Elige la sangría para el formateo: 2 espacios (lo más habitual), 4 espacios o tabulación, según el estilo de tu proyecto.
  3. Pulsa "Formatear / Embellecer" para verlo legible, "Minificar" para comprimirlo, o "Solo validar" para comprobarlo sin tocarlo.
  4. Copia el resultado con "Copiar salida". Todo ocurre en tu navegador: tu JSON nunca se envía a ningún servidor.

Ejemplo práctico

Una API te devuelve esto en una sola línea:

{"nombre":"Ana","ciudad":"Madrid","edad":29}

Al pulsar "Formatear" con 2 espacios, queda así:

{
  "nombre": "Ana",
  "ciudad": "Madrid",
  "edad": 29
}

De un vistazo ves los tres campos y sus valores. Si ahora pulsas "Minificar", vuelves a la versión de una línea, lista para enviar en una petición. Y si el JSON trae un error, por ejemplo una coma después del último campo, la herramienta no lo formatea: te muestra el mensaje de error para que lo corrijas antes de seguir.

Consejos prácticos

  • Valida antes de formatear cuando sospeches un error. "Solo validar" te confirma si el problema es de sintaxis o si el JSON está bien y el fallo está en otro sitio.
  • Usa la misma sangría que tu proyecto. Si tu equipo usa 2 espacios, formatea con 2: un JSON reformateado con otra sangría genera cambios innecesarios en el control de versiones.
  • Minifica solo para enviar. El JSON minificado ahorra ancho de banda en producción, pero nunca lo guardes así en tu repositorio: la próxima persona que lo abra (posiblemente tú) lo agradecerá formateado.
  • Copia el error exacto al buscar ayuda. El mensaje de error del navegador indica la posición aproximada del fallo; pegarlo en tu buscador junto con "JSON" suele llevarte directo a la causa.

Errores comunes que debes evitar

  • Comas finales. En JSON no se permite una coma después del último elemento de un objeto o una lista. Es el error más frecuente al editar a mano, y JavaScript lo perdona pero JSON no.
  • Comillas simples. JSON exige comillas dobles para las claves y los valores de texto. Las comillas simples son válidas en JavaScript, pero no en JSON.
  • Claves sin comillas. En JSON todas las claves deben ir entre comillas dobles: {nombre: "Ana"} no es válido, {"nombre": "Ana"} sí.
  • Comentarios. JSON no admite comentarios. Si tu archivo los tiene, es JSON5 o un formato parecido, y tendrás que quitarlos antes de validarlo aquí.

Preguntas frecuentes

¿Cómo sé si mi JSON es válido?

Pégalo aquí y pulsa «Solo validar». Si es válido, verás la confirmación; si no, verás el mensaje de error del navegador, que normalmente indica qué carácter falló y en qué posición aproximada.

¿Qué diferencia hay entre formatear y minificar?

Formatear añade saltos de línea y sangría para que el JSON sea legible por personas. Minificar quita todos los espacios y saltos innecesarios para que ocupe lo menos posible al enviarlo por red. Son operaciones inversas: puedes pasar de una a otra cuantas veces quieras sin perder datos.

¿Qué sangría debo elegir: 2 espacios, 4 espacios o tabulación?

La que use tu proyecto. 2 espacios es lo más común en JavaScript y en la mayoría de APIs; 4 espacios es habitual en Python; la tabulación aparece en algunos proyectos antiguos. Lo importante es ser constante, no la opción en sí.

¿Mi JSON se sube a algún servidor?

No. El análisis se hace en tu navegador con JavaScript. Ni el JSON de entrada ni el resultado salen de tu dispositivo, así que puedes validar datos de trabajo o con información sensible sin riesgo.

¿Puedo validar JSON con comentarios o comillas simples?

No: eso no es JSON estricto, sino JSON5 o código JavaScript. Esta herramienta aplica las reglas del JSON estándar, así que los comentarios y las comillas simples darán error. Quítalos antes de validar.

¿Por qué el error dice algo en inglés aunque la página esté en español?

El mensaje detallado del error lo genera el propio navegador, no la página, y por eso aparece en el idioma del navegador. La parte importante —qué carácter falló y dónde— se entiende igual: busca esa posición en tu JSON.
